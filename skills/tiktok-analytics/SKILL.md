# TikTok 账号数据分析

用 `tiktok-scraper` MCP 工具抓取公开主页的视频数据，再给出**结论 + 动作**，不要只堆数字。

## 流程

1. **定参数**（用户没说就用默认，不要追问）
   - 账号：用户给的 @用户名；多个账号一起抓。
   - 日期：「本月」→ `preset: thisMonth`；「上周」→ `lastWeek`；具体日期用 `from`/`to`（YYYY-MM-DD，曼谷时间）。默认本月。
   - 对比：复盘默认 `compare: lastMonth`（上月同期，严格同日期）；「环比/上一周期」→ `previous`；「上周同期」→ `lastWeek`；用户说不对比才用 `none`。
2. **抓取**：调用 `start_scrape`。没完成会返回任务 ID 和进度 → 告诉用户一句「正在抓取 @xx，第 N 步」，然后继续 `get_scrape(job_id)` 直到完成。一个账号通常 1–3 分钟。
3. **需要细节时**：`list_videos`（爆款、挂车视频、对比期视频）；要文件时 `export_report`（默认 xlsx，存到下载文件夹，把路径给用户）。
4. **首次使用 / 报错**：先 `doctor`。它会自动在后台安装依赖和浏览器，提示用户 1–3 分钟后重试即可。

## 读结果的规则

- `compare.insufficient` 有值 = 对比期数据没抓全（账号历史没加载到那么早），**不能下涨跌结论**，直接说明哪个账号缺到哪天。
- 两期天数不同（`compare.sameSpan=false`）看日均 / 条均，不比总量。
- `cart.fallback` 为真 = 某组样本 <3 条，剔除最高最低不成立，已按条均算，结论要标「样本少」。
- `accounts[].error` 是该账号失败原因（多半是网络或主页打不开），如实告诉用户，可建议重新抓取。
- 数字只用工具返回的，不估算、不补全。

## 回复格式（简洁、排版清楚）

```
**@账号 · 11-01~11-17 vs 上月同期**

| 指标 | 本期 | 对比 | 变化 |
|---|---|---|---|
| 视频数 | 20 | 18 | ▲11% |
| 总播放 | 125万 | 98万 | ▲27% |
| 条均播放 | 6.3万 | 5.4万 | ▲15% |
| 互动率 | 6.4% | 5.9% | +0.5pp |

**结论**
- 一句话说清整体是涨是跌、主要原因（如 1 条爆款贡献 35% 播放）

**下一步**
1. 具体动作（如：挂车视频条均播放比非挂车低 52%，挂车视频改用 xx 开头结构，先测 3 条）
2. 发布时间调到 14:00 前后（该时段条均最高，样本 ≥2 条）
```

- 先结论后数据；表格最多 5–6 行核心指标。
- 动作要具体可执行（拍什么、什么时间发、哪类视频挂车），每条附一个依据数字。
- 多账号时加一行账号对比，指出哪个号拉动/拖累。
