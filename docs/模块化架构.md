# 模块化架构

> 目标：主程序保持最小，功能按需装配。用户装完打开只有基础能力，需要什么就在设置里下载什么。

## 一句话结构

```
核心（始终在）      单视频提取
默认模块            主页批量抓取
可下载模块          挂车对比 / 趋势图 / 品牌聚合 / 内容分析 / 视频下载 / Shop GMV / Marketing / 发布
```

模块**不随主程序分发**，在设置里按需下载。这样主程序体积和界面复杂度都不随功能增长。

## 目录布局

```
<可写基目录 BASE_DIR>/
├── settings.json            用户设置（模块开关 + 非敏感配置）
├── modules/                 已安装的模块
│   ├── video-download/
│   │   ├── module.json      清单
│   │   ├── server.js        服务端：注册路由
│   │   └── public/          前端：module.js / module.css
│   └── shop-gmv/
├── data/jobs/               抓取任务
└── app.log
```

开发态（源码运行）`BASE_DIR` 就是项目目录，模块放 `./modules/`。

## 模块清单 `module.json`

```json
{
  "id": "video-download",
  "name": "视频下载",
  "version": "1.0.0",
  "description": "单个 / 批量 / 主页 / vid 四种模式下载无水印视频",
  "author": "liyangru",
  "core": ">=1.0.0",
  "requires": [],
  "config": [
    { "key": "outDir", "label": "下载目录", "type": "path", "default": "" }
  ],
  "secretConfig": [
    { "key": "TTS_APP_KEY", "label": "App Key" }
  ]
}
```

- `requires`：依赖的模块 id，**开启时自动级联开启**（依赖缺失则拒绝）。
- `config`：非敏感配置，存 `settings.json`。
- `secretConfig`：敏感配置，存 `.env`（**永不进 settings.json，永不进 git**）。

## 安全边界

| 项 | 做法 |
|---|---|
| 密钥 | 只存 `.env`；设置页只显示「已配置 / 未配置」，不回显明文 |
| 模块来源 | 只从本仓库的 GitHub Release 下载 |
| 完整性 | `index.json` 里带每个模块 zip 的 **sha256**，下载后校验，不匹配直接拒绝 |
| 执行 | 模块在**主进程内**运行（不做沙箱）—— 所以只安装本仓库的模块，设置页要明确提示这一点 |

> ⚠️ 诚实说明：这是**同进程插件**，不是沙箱。模块代码有主程序的全部权限。所以模块来源必须是可信的（本仓库），这一点要在界面上写清楚，不能装作是安全的沙箱。

## 模块索引 `index.json`

放在仓库 `modules/index.json`，随 Release 一起发布。应用从
`https://raw.githubusercontent.com/liyangru/tiktok-scraper/master/modules/index.json` 拉取。

```json
{
  "modules": [
    {
      "id": "video-download",
      "name": "视频下载",
      "version": "1.0.0",
      "description": "...",
      "size": 12345,
      "sha256": "…",
      "url": "https://github.com/.../releases/download/modules-v1/video-download-1.0.0.zip"
    }
  ]
}
```

## 运行时接口

### 服务端（模块 `server.js`）

```js
module.exports = {
  register(app, ctx) {
    // ctx: { baseDir, dataDir, settings, log, core: { scraper, report, browsers } }
    app.get('/api/video-download/...', handler);
  },
};
```

模块能用到核心能力（抓取 / 报表 / 浏览器定位），但**不能改核心的字段模型** ——
需要新字段就提核心版本，避免模块之间互相打架。

### 前端（模块 `public/module.js`）

```js
window.TTModule.register({
  id: 'video-download',
  title: '视频下载',
  mount(el, ctx) { /* 渲染到设置页/主界面的挂载点 */ },
});
```

主界面给模块两个挂载点：`#module-panels`（主区域面板）和 `#settings-modules`（设置项）。

## 核心 API

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/modules` | 索引 + 已安装 + 启用状态 |
| `POST` | `/api/modules/:id/install` | 下载并安装（校验 sha256） |
| `DELETE` | `/api/modules/:id` | 卸载 |
| `POST` | `/api/modules/:id/toggle` | 启用/停用（自动级联依赖） |
| `GET` | `/api/settings` | 读设置（密钥只返回是否已配置） |
| `POST` | `/api/settings` | 写设置（密钥写入 .env） |

## 分期

- **P0**：设置系统 + 模块注册表 + 安装/卸载/启停 + 设置界面 + 索引拉取
- **P1**：把「主页批量抓取」从核心能力改成默认模块；「单视频提取」留在核心
- **P2**：第一个可下载模块 **视频下载**（单/批量/主页/vid 四种模式）打通全链路
- **P3**：趋势图 / 品牌聚合 / 内容分析 / 挂车对比 逐个模块化
- **P4**：Shop GMV / Marketing / 发布（需要凭据与授权）
